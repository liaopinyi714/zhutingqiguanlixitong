# 聆序 · 助听器客户管理 Demo

面向助听器门店的客户与服务档案工作台。代码使用 Git 管理，首版适合体验与评审，所有内置资料均为虚构。

## 已实现

- 12 份虚构客户档案；新建、编辑、按服务阶段筛选。首页中央搜索框、侧栏搜索框及 `Ctrl/⌘ + K` 可跨客户资料、检查结论、设备和随访记录检索，并直接打开档案。
- 纯音听力图：125–8000 Hz，左右耳气导、骨导、逐点掩蔽、无反应、四频平均听阈、历史对比、打印/PDF。
- 言语测听及其他检查结果文本、结论与建议。
- 设备品牌型号、左右耳、序列号、成交金额、保修期和验配调试说明。
- 门店自建助听器型号字典：品牌 → 系列 → 型号；店主可添加、改名与停用，录入验配时逐级选择。旧验配记录保留保存时的名称。
- 随访预约、逾期提示、完成结果及服务历史。
- PDF/JPG/PNG 私有附件上传与鉴权下载（单文件 10 MB）。
- 客户来源、年龄、阶段、随访类型与完成情况统计。
- 店主、验配师、前台的演示角色；服务端写入权限和门店隔离；审计记录。
- 店主 JSON 导出：包含档案、检查、验配、随访、型号字典、附件目录和审计。附件文件需单独下载。

## 本地运行

需要 Node.js 24 和 pnpm 11。Windows、macOS、Linux 均可。

```sh
git clone https://github.com/liaopinyi714/zhutingqiguanlixitong.git
cd zhutingqiguanlixitong
pnpm install
pnpm build
pnpm db:local
pnpm dev:api
```

打开 http://127.0.0.1:8787 ，选择演示角色进入。D1 和 R2 使用 Cloudflare 本地模拟器，数据在 `.wrangler/state/`，刷新页面或重启服务不会清空。不要将该目录提交 Git。

开发时保持 `pnpm dev:api` 运行，再开一个终端执行 `pnpm dev`，访问 http://127.0.0.1:5173 。Vite 会将 `/api` 代理到 8787。

```sh
pnpm test   # 听力规则、API 权限、门店隔离与持久化测试
pnpm build  # TypeScript 检查与生产构建
```

## 体验顺序

1. 选择店主进入，从首页醒目的搜索框查找客户；可输入姓名、电话、设备型号或检查与随访内容，也可按 `Ctrl/⌘ + K`。
2. 打开陈淑华的档案，查看听力图、设备和随访。
3. 在门店设置中添加一个虚构品牌、系列和型号；新建一位虚构客户，录入检查，并在验配表单中选择该型号，再安排随访。
4. 回到随访页，填写联系结果；刷新后再次查看档案。
5. 上传一份虚构报告，验证下载；切换前台，确认专业检查录入不可用。

## 项目结构

```text
src/                 React 工作台、SVG 听力图、响应式样式
server/domain.ts     听力数据规则、校验、角色能力
server/index.ts      Hono HTTP 接口及数据库/文件调用
migrations/          D1/SQLite 建表、演示数据与型号字典迁移
tests/               业务和接口测试
docs/                部署、迁移及版本边界
wrangler.jsonc       Cloudflare 运行配置
```

前端通过 HTTP JSON 接口与后端通信，SQL 数据和文件分别保存。Hono 路由、SQL 与文件调用目前处于同一个服务端模块；正式版应继续拆分仓储接口并验证 Node.js 部署适配。迁移到 PostgreSQL 需要转换建表和部分 SQL，不能直接执行 D1 的 SQLite 迁移文件。

## 演示边界

`DEMO_MODE=true` 允许任何访问者选择演示角色，只用于虚构数据。它不是正式员工认证。设置为 `false` 会关闭新演示登录，但不会使本版本变成生产系统；已有会话最长 24 小时，需要在切换环境时清理会话。

尚未实现真实员工注册/登录与找回、儿童专门验配流程、仪器自动导入、结构化言语测听/声导抗、自动消息通知、多门店管理界面、完整备份恢复、历史资料批量导入及数据修订版本。不要把演示角色权限或 JSON 导出称为完整的生产安全与备份方案。

听力图与平均值用于记录展示，不自动诊断疾病、不自动给出选配处方。内置设备名称仅作示例。

详见 [部署指南](docs/DEPLOYMENT.md) 和 [设计与迁移说明](docs/ARCHITECTURE.md)。
