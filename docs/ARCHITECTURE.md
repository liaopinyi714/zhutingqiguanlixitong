# 设计与后续迁移

## 当前数据关系

一个门店拥有多位客户；每位客户拥有多次听力检查、验配、随访、附件和审计事件。所有表都带 `tenant_id`，服务端从会话取得门店归属，不接受客户端传入的门店身份。读取附件、客户详情和随访更新均校验归属。

助听器字典以 `device_brands`、`device_series`、`device_models` 三级表按门店保存。新验配记录可引用型号 ID；服务端核对型号与门店后，把品牌、系列、型号名称一并写入当次验配快照。因此字典改名或停用不会追溯修改历史记录。停用上级会一并停用下级，原始字典行保留用于审计与迁移。

客户基本信息为独立字段，住址、其他联系人姓名和其他联系人电话分别存储。同页建档通过一个接口和 D1 批处理一次保存客户、可选的听力检查、验配与首次随访。听力检查和验配内容在 Demo 中保存为带校验的 JSON 文本，方便保留原始测点。后续需要按检查项目统计时，可将测点、设备和言语测听拆为关联表并编写迁移。检查、验配和随访支持在原记录上修改；操作留审计，但当前未保存修改前的字段快照。客户、服务记录和附件使用 `deleted_at` 软删除；普通档案、搜索、随访统计、报告下载和保修提醒排除已删除资料。删除客户时暂留关联记录与附件，恢复客户后重新可见。

恢复期限为删除时间起 30 天。服务端拒绝恢复已过期记录，页面只显示期限内的记录。Worker 每天运行清理：先删除到期的 R2 对象及附件目录，再清除到期服务记录和客户档案；附件清理未成功时保留客户数据库行供下次重试。已到期客户的关联审计一并清理，仍在使用中的客户保留操作审计。备份若包含已删除资料，还需在正式版定义独立的备份保留与销毁规则。

保修提醒从未删除的验配快照读取保修截止日期，当前统计展示已到期和未来 90 天内到期的记录，并关联客户。一个客户的多台设备可以各出现一条。

全局搜索按门店查询客户字段和检查、验配、随访文本。当前数据量小，使用参数化 `LIKE` 查询；词长受 D1 的 50 字节模式限制。客户量增长后应改成可迁移的搜索索引，并重新评估模糊匹配的速度和中文分词。

金额当前记录为元，用于客户档案展示。正式版涉及金额运算时迁移为整数分，避免浮点误差；本系统不承担财务记账。

## 听力数据

频率覆盖 125、250、500、750、1000、1500、2000、3000、4000、6000、8000 Hz。每个气导/骨导测点分别保存值、掩蔽和无反应标记，`null` 表示未测。

四频平均值使用 500、1000、2000、4000 Hz 的气导阈值；任一缺测或无反应即不显示平均值。不自动分类听力损失、不生成诊断或验配处方。语音及其他检查目前保留文字结果和原始附件，待专业流程评审后扩充结构化项目。

## 部署结构

浏览器 → Hono HTTP API → D1（档案、会话、目录）/ 私有 R2（报告）。前端为 Vite 静态文件，Workers Static Assets 托管。库版本由 `pnpm-lock.yaml` 锁定。

## 迁移路径

1. 前端可以部署到任何静态网站服务，修改接口地址配置。
2. Hono 可增加 Node.js 入口，当前业务校验函数可复用；Cloudflare 绑定需要改为数据库和文件适配器。
3. D1 导出 SQL 或使用应用导出结构化资料。迁往 SQLite 可复用大部分表结构；迁往 PostgreSQL/MySQL 需转换方言、JSON 查询和迁移脚本。
4. R2 对象通过 S3 兼容工具迁移至目标存储。保留对象清单和校验值，验证每个附件与客户关系。
5. 正式切换前做完整备份，在目标环境验证行数、金额、日期、测点、权限和附件。最后安排短暂停写、增量同步和入口切换，保留回退方案。

GitHub 保存源代码与迁移脚本，不保存业务数据。迁移必须同时考虑代码、数据库、对象文件和配置。

## 后续正式版工作

- 真实身份认证、管理员授权、会话撤销、登录限流。
- 修订历史、重复档案合并、归档和数据保留规则。
- 结构化检查项目、试戴与调试区分、设备按耳管理、量表和服务模板。
- 历史资料导入及错误预览、完整备份恢复与定时任务。
- 多门店管理、角色与字段权限配置、正式 API 契约与版本策略。
- 长期保存并可恢复的表单草稿、失败重试和保存冲突处理。
- 明确大陆网络体验、真实资料的数据所在地与处理要求后，再决定正式托管组合。
