# 压测结束后的生产收尾

核对日期：2026-10-01。代码收尾和线上清理是两个步骤。SQL 由操作者在 Cloudflare 执行；Git 推送、测试和部署成功都不能替代线上剩余数量核验。

## 1. 构建与诊断

1. 在 Worker 的 **Settings → Builds → Build Variables and Secrets** 删除 `LOAD_TEST_CUSTOMERS` 和 `LOAD_TEST_STORE_ID`，保存。若以前误加到运行时 Variables and Secrets，也删除这两个同名项。保留员工 Secret、Access、资源 ID、Node/pnpm 版本及其他正常配置。
2. 构建命令仍为 `pnpm run build:cloudflare`，部署命令仍为 `pnpm exec wrangler deploy --config wrangler.jsonc`。不要额外执行 seed 命令，也不要 Retry 旧的压测提交。
3. 发布最新收尾提交。该版本移除了远程导入器和 seed 命令，旧变量不会触发导入；配置脚本会提示删除遗留变量，不把它们发布为运行时绑定。
4. 核对最新部署成功。DevTools Network 中 `/api/config`、`/api/me`、`/api/summary` 默认不再返回项目的 Server-Timing。Cloudflare 自身追加的计时或其他平台响应头不由项目控制。

## 2. 清理前只读核验

1. 临时停止对压测客户的编辑，不暂停或撤销账户权限。
2. 在 **Storage & databases → D1 SQL Database** 选 `hearing-care-production`，打开 **Console**。核对 Worker 的 DB 绑定确实指向此库。
3. 执行 [只读剩余数量 SQL](../maintenance/2026-10-load-test-verify.sql)。记录七个数量；只输出数量，不显示客户或账号资料。
4. 清理会物理删除测试记录。需要恢复余地时，先在 D1 Time Travel 记录当前恢复时间/书签；若库中已有真实资料，先按 [备份](BACKUP.md) 保存数据库及附件。不要删除数据库、门店或员工名单。

## 3. 执行一次性清理

打开 [清理 SQL](../maintenance/2026-10-load-test-cleanup.sql)，将编号 1–6 的六个 DELETE 语句按顺序粘贴到 D1 Console 分别执行，每个以分号结束。可以在控制台支持多语句时一起提交，但不假定多个独立操作具有事务性。某条失败时停止，处理后从编号 1 重跑；已清理记录不会重复删除其他数据。

顺序为维修 → 听力 → 随访 → 验配 → 安全可删除测试客户的审计 → 测试客户。

识别规则同时校验本次固定批次 `loadtest-20261001`、门店 ID 的 UTF-8 十六进制编码、六位编号 000001–050000、原始记录类型和生成的关联关系。覆盖各测试门店、已编辑/软删除的原始测试记录；不按姓名、电话、日期或通用前缀删除，不创建表/索引或关闭外键，也不修改账户、门店、成员、会话、Access 或 STAFF_ACCOUNTS。

如果压测客户有额外的手工业务记录、改换关系的记录或上传附件，脚本会保留该客户及仍被引用的设备，不能自动假定这些新内容也是虚构资料。导入器本身没有创建任何附件或 R2 对象，清理 SQL 因而不删除附件目录。额外附件应在网页删除对应测试客户/报告，走现有 30 天恢复与 D1/R2 成套清理流程；需要立即清理时先核对再另行维护，不能只删 D1 目录而留下 R2 文件。

删除也计入 D1 写入额度。遇到明确的免费额度错误，等待下一个 UTC 日（北京时间 08:00）再继续，不切换付费计划、不重复导入。[D1 额度说明](https://developers.cloudflare.com/d1/platform/pricing/)

## 4. 清理后验收

1. 再运行只读核验 SQL。七项均为 0 才说明此批次及关联目录没有遗留；非零时不要宣称清理完成，应核对被保护的手工资料或附件。
2. 执行 `PRAGMA foreign_key_check;`，应返回空结果。
3. 刷新网站，核对客户、设备、维修、随访与统计不再包含压测记录；实际已有真实资料继续保留。
4. 核对账户、头像、门店、同事关系和登录仍正常。

清理 SQL 不进入 migrations-production、构建、Worker、CI 或 Cron；保留在 maintenance 中供本次核验与必要重试，不能作为日常清库命令。数据库正式结构和正常备份、迁移、安全检查不变。

## 5. 验证覆盖

内存 SQLite 测试复现 1000/10000 客户、多店及 UTF-8 门店编码，验证关联清理、真实同名资料保护、错误编码/越界编号/额外版本保护、附件与手工维修保留、部分执行后的重试、外键与结构不变。构建测试用临时配置核对旧变量失效、无远程导入入口、正常资源校验仍生效。它们不读取或修改线上数据库，不代表实际云端已经执行清理。
